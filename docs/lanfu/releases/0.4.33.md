# 0.4.33 命名体系第一轮：配置文件更名 lanfu.json

本轮是"去 openclaw 命名"三轮计划的第一轮（员工可见层）。

## 主要变更

- **配置文件更名 `openclaw.json` → `lanfu.json`**：
  - 网关启动时自动迁移——旧名文件存在且新名不存在时一次性物理改名，内容不变；`clawdbot.json` 时代的老文件同样迁移；两者并存时新名优先、旧文件不动。
  - 显式 `OPENCLAW_CONFIG_PATH` 覆盖、只读/Nix 模式、测试环境不迁移。
  - Windows 安装器新装写 `lanfu.json`；升级安装自动识别旧名文件（读旧写旧，随后由网关迁移）。
- **CLI/向导可见文案去 openclaw**：首次安装向导（中/繁/英三语种）中的命令示例全部改为 `lanfu …`；doctor/security/plugins/skills/config 等命令提示同步更名；网关密钥存储位置说明改为 `~/.lanfu/lanfu.json`。
- **Web UI 可见文案去 openclaw**：登录引导、配对页"一条命令"、更新失败排查（`lanfu triage`）、MCP 命令卡片、"在终端继续会话"复制命令等改为 `lanfu …`。
- **版本横幅去品牌**：`LanFu 0.4.33 (OpenClaw 2026.9.6)` → `LanFu 0.4.33 (core 2026.9.6)`（上游兼容版本号保留，品牌字样移除）。
- **桌面端**：配置页副标题与六语种资源中的 `openclaw.json` 字样改为 `lanfu.json`；原生网关配置路径优先使用新名（旧文件回退可读）；README 同步。
- **文档**：管理员手册/部署指南/打包指南改为新文件名并注明自动迁移；SecretRef 凭据矩阵与凭据面文档按当前注册表重生成（顺带清除了 0.4.30 删渠道后遗留的 discord/whatsapp 过期词条）。
- **修复**：vitest worker 声明清单里 0.4.30 删渠道后残留的 discord 条目（导致本机 secrets 套件无法启动）；两处历史遗留的陈旧测试断言（Windows 计划任务名、向导 scoped translator telegram 断言、`--version` 快路径断言）。

## 行为兼容

- 旧版本升级后首次启动网关即完成迁移，员工无感知；任何仍指向 `openclaw.json` 的外部脚本在迁移后需改指 `lanfu.json`（legacy 读取兼容在网关侧保留：新名不存在时会回退读旧名）。
- 环境变量前缀 `OPENCLAW_*`、npm 包名 `@openclaw/*`、`npx openclaw`、`docs.openclaw.ai` 外链属第二/三轮范围，本版未动。
