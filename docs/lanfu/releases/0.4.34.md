# LanFu 0.4.34

0.4.33 本机升级验证发现的三处品牌/版本缺陷的根因修复，不引入新功能。

## 修复

1. **CLI 横幅显示旧版本与旧品牌**
   - 现象：`lanfu --version` 输出 `LanFu 0.4.29 (OpenClaw 2026.9.6, …)`，而 0.4.33 发布说明承诺 `LanFu 0.4.33 (core 2026.9.6)`。
   - 根因一：启动器 `openclaw.mjs` 有独立于 dist 的 `--version` 快速路径，0.4.33 只改了 dist 侧格式化器，启动器模板 `(OpenClaw …)` 未同步。已改为 `(core …)`，两处格式一致。
   - 根因二：`lanfu.productVersion` 由流水线在 build job 打标，但 windows-exe / linux-deb 暂存 job 各自重新 checkout，拿的是仓库里上次手动提升的 0.4.29 —— 0.4.30~0.4.33 四个版本的安装包横幅都停在 0.4.29。已在两个暂存 job 补打标（scripts/stamp-product-version.mjs），smoke 测试新增横幅断言（必须以 `LanFu <tag 版本> (core ` 开头且不含 OpenClaw），回归即构建失败。
2. **WebUI 关于页版本徽章显示 v0.1.1**
   - 根因：徽章渲染的是写死在 en.ts 里的 `aboutPage.productVersion` 翻译值（0.1.1 时代遗留），不是真实产品版本。改为从构建身份注入的 `productVersion`（ControlUiBuildInfo）读取，随 tag 自动更新。
3. **WebUI 关于页「基于 OpenClaw 2026.9.6 构建」**
   - 与横幅同类残留。英文源改为 "Built on core 2026.9.6"，zh-CN（基于 core 2026.9.6 构建）/zh-TW（基於 core 2026.9.6 建置）译文同步更新；其余语言该键本就回退英文，显示新英文文案。

## 本地化修复

- **登录页两步引导回退英文**：0.4.33 把英文源里的命令从 `openclaw …` 改成 `lanfu …`，译文按源文本哈希失效，登录失败引导的 step 1/2 在全部 20 个语言回退英文。已更新 zh-CN / zh-TW 译文并重算哈希；其余语言保持英文回退（既有长尾债务，未恶化）。
- 同步 raw-copy 基线（0.4.33 遗留 9 条 `openclaw …` → `lanfu …` 命令串基线未刷新）。

## 验证

- 开发侧：tsgo core/ui/scripts 零错误；launcher 双路径 fixture 实测（有/无 productVersion）；about + build-info 单测 15/15 绿；release-workflow 契约测试无新增失败（既有 ENOENT 基线）。i18n check 的 catalog fallback 漂移为既有状态（本机无翻译 provider，约 27 键待 control-ui-locale-refresh 工作流），CI 不含此检查。
- 用户侧：0.4.32→0.4.33 升级已实测（迁移/网关/dist 平坦/聊天记录保留均通过），0.4.34 发布后重点复验：`lanfu --version` 横幅、关于页徽章与 upstream 行、登录页引导语言。
