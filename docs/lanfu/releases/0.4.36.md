# LanFu 0.4.36

命名第二轮：CLI 提示文案全面切换为 lanfu 命令显示。无新功能，纯显示层品牌切换。

## 变更

1. **CLI 命令提示品牌切换（约 1950 处，~900 文件）**：用户可见的错误提示、恢复指引、帮助与 usage 例子、启动警告、schema 描述、向导与桌面状态页中的 `openclaw <子命令>` 全部改为 `lanfu <子command>`，覆盖 doctor/plugins/update/gateway/devices/pairing/skills/status 等全部命令族，含 `--profile`/`--container` 前缀形态与嵌套引号形态。
2. **网关节点协议提示同步**：gateway-protocol schema 的节点 update-required 问题提示（`lanfu update` / `lanfu node restart`）与连接失败恢复提示（`lanfu devices approve/rotate/list`）改为 lanfu，员工照着敲不会再看到 openclaw。
3. **显示层与真实包名分离原则**：真实包名/二进制仍为 `openclaw`——`npx openclaw`、`@openclaw/*` 包名、`OPENCLAW_*` 环境变量、`.openclaw` 迁移路径、update-run 台账标识符、shell 补全引擎（按真实 bin 名匹配）与 `Usage:` 横幅均保留 openclaw。
4. **顺带修复**：36 个源码-测试失配（源码已切换而配对断言滞后的测试断言对齐），并修复 9 个基线红文件（cli 3 + commands 6）。

## 范围外遗留（归后续波次）

- `apps/`（Swift 上游）、`crates/`（Rust）、`extensions/`（canvas 除外，本轮已随门禁修复）约 1250 处命令串；
- `/openclaw` 聊天斜杠命令簇（改文案须同步解析器，需产品决策）；
- 语音唤醒词与中止触发词（行为变更，需产品决策）；
- `Usage: openclaw` 横幅与补全引擎（依赖真实 bin 名，归第三轮显示层别名波次）。

## 验证

- 开发侧：tsgo core/ui/scripts 零错误；cli/commands 双套件 vs 0.4.35 基线**严格无新增失败**（cli 65→62、commands 83→77，顺带修复 9 个基线红文件）；doctor 健康检查/插件降级态等定向测试全绿；发布门禁（每版说明存在性）通过。
- 用户侧：发布后本机 0.4.35→0.4.36 升级复验（横幅/CLI 提示抽查）。
